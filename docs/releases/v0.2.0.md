# plat-operations v0.2.0

First release with published artifacts. It is the first version published to
PyPI (`plat-operations`) and to GHCR (`ghcr.io/paintbrushv/plat-operations`).
The `v0.1.0` git tag marks the initial import of the repository, with no
GitHub release, package or image. Version 0.1.1 appeared only in the source
tree and was never tagged.

This release is the `main` branch plus PR #25 (OAuth 2.1 token introspection).
Pull request numbers below refer to
[paintbrushv/plat-operations](https://github.com/paintbrushv/plat-operations/pulls).

## What the release contains

### Exact-cent core (PRs #3, #4, #14)

- `boxscore-exact` does the arithmetic in checked signed integer USD cents. GL
  imports, snapshot money, variance, corrections, issued totals and SQLite
  persistence all use cents; money crosses the JSON boundary as decimal
  strings with at most two places. Floats, exponent notation, NaN and excess
  precision are refused (#3).
- Accounts are matched by account code across actual and budget labels, and
  conflicting categories are refused (#4).
- Imports create immutable revisions. A correction names the current revision
  and a reason. Issued reports are immutable records, and a reviewed copy
  migration moves data from a legacy database (#3).
- Calculation catalog (#14): every function has a name, a version, JSON
  Schemas for input and output, and a versioning policy. Every response is a
  provenance envelope with `contract_version` (`plat.ops/1`), `function` and
  `version`, `producer` (name, version, arithmetic), `input_sha256`,
  `output_sha256`, `computed_at`, `status` (`calculated`, `review_required` or
  refused), and the `result` or the refusal.
- See [docs/EXACT_CENTS.md](../EXACT_CENTS.md) and
  [docs/PROVENANCE.md](../PROVENANCE.md).

### Source adapters (PR #20)

Imports go through a source adapter selected by a versioned profile id
(`name/N`). Two adapters are registered: `canonical.csv/1` (canonical GL CSVs
plus an optional snapshot JSON object) and `canonical.json/1` (one canonical
period dataset). `boxscore-exact adapters` prints the specs and
`import-with --profile` runs one. The stored revision records the profile and
the SHA-256 of each file read. How to write and version a new adapter is in
`boxscore/docs/DATA_CONTRACTS.md`.

### Trace log and citation (PR #19)

Every catalog call, including refusals, gets a UUID v4 `trace_id` and a
one-line `citation` in its envelope naming `function@version`, the trace id and
the first 12 hex characters of the input and output hashes. With a database the
call is also appended to the `exact_invocations` table, which refuses UPDATE and
DELETE. Without one, `BOXSCORE_TRACE_DIR` selects an `invocations.jsonl` file;
otherwise nothing is recorded and `trace_store` is `"none"`. A tracing failure
never fails a calculation. `boxscore-exact trace` and `get_provenance` read a
record back. The database schema version is now 2 (see
[Upgrading](#upgrading)).

### MCP over stdio (PR #15)

`boxscore-exact mcp` serves the catalog as a Model Context Protocol server over
stdin and stdout (JSON-RPC 2.0, protocol `2025-06-18`, `2025-03-26` accepted),
for Claude Desktop. See [docs/connectors/claude-desktop.md](../connectors/claude-desktop.md).

### MCP over streamable HTTP (PRs #21, #25)

`boxscore-exact serve` serves the same dispatcher over HTTP: `POST /mcp`
(streamable HTTP), `POST /v1/calc/{function}`, `GET /openapi.json`,
`GET /health` and the RFC 9728 protected-resource metadata. It binds to
`127.0.0.1:3819` by default and refuses a non-loopback address without a
validator. See [docs/connectors/remote-mcp.md](../connectors/remote-mcp.md)
and [docs/connectors/openapi.md](../connectors/openapi.md).

- API keys (#21): a key file of `key_id:secret` lines, compared in constant
  time, with a per-caller rate limit (default 60 requests a minute).
- OAuth 2.1 (#25): the server acts as the resource server and checks each
  access token by RFC 7662 introspection against the customer's identity
  provider. It requires the token to be active and unexpired and to carry the
  configured audience and scope (default `boxscore:calc`), and it caches
  verdicts by token hash. Introspection calls to the identity provider are
  bounded. API keys and OAuth can be enabled together.
- Limits: local JWT validation against a JWKS is not implemented, so identity
  providers without an introspection endpoint (Auth0 and Microsoft Entra ID,
  according to the documentation) cannot be used. The claude.ai and ChatGPT
  connector walk-throughs in remote-mcp.md are marked unverified.
- A conformance suite (#23) checks that the catalog, MCP stdio and HTTP return
  identical envelopes for a golden corpus.

### Container image with signed SBOM (PR #22)

`boxscore-exact` is packaged from the root `Dockerfile` as a distroless image:
one binary, non-root user 65532, no shell. Nothing listens unless `serve` is
started. `scripts/check_image.py` checks the image configuration, filesystem
and behaviour (describe, init, import, review, MCP stdio, and `serve`) in CI.

On a `v*` tag, `release.yml` calls `image.yml` with `push: true`. The publish
job pushes the tested image to `ghcr.io/paintbrushv/plat-operations` as `0.2.0`
and `sha-<7 hex>` (`linux/amd64`; there is no `latest` tag), signs it with
cosign keyless signing, attaches the image SBOM (SPDX JSON) as a signed
attestation, and verifies both. A second SBOM of `boxscore/Cargo.lock` is
uploaded as a workflow artifact. To verify an image yourself, see
[Verify the image](../INSTALL.md#verify-the-image) and
[DATA_FLOW.md](../DATA_FLOW.md#8-how-to-verify-the-image).

### Python wheels (PR #5)

The Python distribution `plat-operations` installs the native `boxscore-exact`
command (`pip install plat-operations==0.2.0`). The `wheels.yml` matrix builds
wheels for Linux x64 (`x86_64-unknown-linux-gnu`, manylinux 2_28), macOS Intel
(`x86_64-apple-darwin`), macOS Apple Silicon (`aarch64-apple-darwin`) and
Windows x64 (`x86_64-pc-windows-msvc`), plus an sdist that is rebuilt in
isolation. Each wheel is installed and checked with `scripts/check_native.py`
on Python 3.12 and 3.11. The package requires Python 3.11 or later, and the
release workflow publishes only after the wheels, the sdist and the Rust tests
pass.

## Fixes (PRs #6 to #13)

Fixes to input handling and calculation logic found in review. The legacy
`boxscore` commands still store money as `f64`; none of these PRs changes that.
PR #6 applies to the exact-cent path.

| PR | title |
|---|---|
| #6 | fix(exact): refuse whitespace-padded account codes instead of splitting accounts |
| #7 | fix(parse): refuse NaN/inf cells and unbalanced parentheses in parse_money |
| #8 | fix(ingest): validate the whole CSV before any write and refuse unknown categories |
| #9 | fix(variance): key accounts on code and category; fold T12 category case; normalize close-readiness period |
| #10 | fix(mapping): match category patterns on word boundaries and never classify fees as income |
| #11 | fix(gl-transactions): accept numeric parquet amount types and refuse non-numeric ones |
| #12 | fix(connectors): refuse vendor footer rows in rent roll and aged receivables ingest |
| #13 | fix(collections): count zero on-time rows in the average; skip only blank cells |

PR #16 also includes a fix that verifies the stored input hash before serving
snapshot metrics.

## Upgrading

- There is no earlier published version. The exact-cent database schema is 2.
  A schema-1 database made by a source build from before the trace log (#19)
  is refused with `SCHEMA_MISMATCH`; re-import the data or use the reviewed
  copy migration in [docs/EXACT_CENTS.md](../EXACT_CENTS.md).
- OAuth introspection makes one outbound connection, to the identity provider,
  so `--network none` cannot be used with it.
  [DATA_FLOW.md](../DATA_FLOW.md) describes this.
